# 碧水沃野 · 规则书

> 文档说明
> 版本：**v0.2-draft-r16.2**（基于《植物水网拼图游戏｜策划案 v0.1》的规则增量。当前规则主线：5 维地块 + 5 种边基础地形（含 `BANK` 河岸）；河流不贡献水源、不入水网，`BANK↔WATER` 改写为水渠（每边 6 点、可叠加）；§7 回合流程（开局长牌 + 抽牌 + 二选一动作 + 每回合结算窗口）。**本轮（r16）植物规则重构**：①**种植动作统一**——放置完地块后可在**当前玩家本回合刚放置、未被植物占据且含可种植土地的地形块**上种植（不再选择历史地块），原"扩张"动作取消，改为**自动扩张**（§5.4.2：新地块与已种植地块相邻且土地连通时，植物自动扩张上去，不消耗种子）；②**每格一株**（§5.1）——已被任何植物（不论归属）占据的地块不能再被选择；③**物种优先级与驱逐**（§5.4.1）——同一土地块内出现不同物种时按树>花>草驱逐，立即移除并退还种子，己方植物同样互赶；④**闭合结算二元化**（§5.6）——土地块全封闭时一次性判定：水量足够 → **收获**（退种子、植物保留占格、参与计分），水量不足 → **死亡**（退种子、移除、格空出）；缺水不再有可逆中间形态，"水网也须全封闭"前置条件取消；⑤**同级竞争计分**（§6.3）——同物种跨玩家共存时，数量多者独得该物种全部得分、相同则平分。r15 的三形态（健康/缺水/枯萎）、草优先分水算法、终局枯萎升级随本轮废除。**r16.1 增量（2026-09-05 拍板）**：⑥**多土地地块一次种满**（§5.1）——中心 EMPTY 多 land 边的地块一次种植/扩张覆盖其全部 `land_region`，每区域独立结算、计分（"多次计算"落地）与退种；⑦**收获锁定区域**（§5.6.1）——含收获植物的区域禁种（含原主）、V_L 冻结，收获植物结构性免疫驱逐；⑧**区域退种**（§5.4.1 / §5.6.2）——种子退还以连通区域为单位，每次结算事件每位玩家退 1 枚，与株数无关。
> **r16.2 增量（2026-09-05 确认）**：主动种植的目标收窄为当前玩家本回合刚放置的地块；其它历史地块不能被悬停、点击或作为主动种植目标。§5.4.2 的自动扩张保持不变。
> 工作名沿用策划案：当前运行时界面使用中文标题 `碧水沃野`；旧视觉研究截图中的 `VERDANT WATERS` 仅作历史原型记录。

## 1. 名词表

本规则书新增或重新定义的概念（其余已在策划案 §2 中定义的概念继续沿用：

| 名词 | 定义 |
| --- | --- |
| **地块 5 维结构（Tile5D）** | 一个地块用 5 个独立字段描述：北、东、南、西四条边各一种地形，中心一种地形。 |
| **边基础地形（Edge Base）** | 一条边可取的 5 种基础地形：`LAND`、`EMPTY`、`WATER`、`RIVER`、`BANK`（河岸）。`BANK` 是专为河流地块新增的"河岸"地形，可与 `EMPTY` 或 `WATER` 同型对接（详见 §3.2）。 |
| **边修饰（Edge Modifier）** | 可叠加在边基础地形之上的标记，目前仅有一种：`IRRIGATION`（含灌溉节点）。修饰只作用于 `LAND` 和 `WATER`。 |
| **中心地形（Center Terrain）** | 一个地块中央格可取的 4 种地形：`CENTER_LAND`、`CENTER_EMPTY`、`CENTER_LAKE`、`CENTER_RIVER`。 |
| **含灌溉节点的边（Irrigated Edge）** | 带有 `IRRIGATION` 修饰的 `LAND` 或 `WATER` 边。它在拼接时不影响类型判定，但在水源结算里区分"水能否灌溉到 land"。 |
| **水源地块（Water Source Tile）** | 一块实际为所连接的水网贡献水源点数的地块。现行规则下，`RIVER` 边与 `CENTER_RIVER` 中心**不贡献水源**，所以"河流地块"不算水源地块；只有 `WATER` / `WATER_WITH_IRRIGATION` / `LAND_WITH_IRRIGATION` 边的地块、以及 `CENTER_LAKE` 地块，按 §4.1 贡献水源。 |
| **水渠（Canal）** | 河流地块的 `BANK` 边与外部水口边对接时，被永久改写后形成的"水口边"——它在常规水口基础上额外为所在水网贡献 **6 点**水源容量；多条水渠边对同一水网独立贡献，可叠加。详见 §2.4.4、§4.1。 |
| **种子（Seed）** | 玩家可用的植物苗源。每位玩家拥有自己的种子集合，集合内三种植物（草 / 花 / 树）并存，详见 §5。 |
| **植物状态（Plant State）** | 同一地块上的植物在任意时刻处于**存活（Surviving）**状态；土地块全封闭结算时一次性转为两个终局状态之一：**收获（Harvested）**或**死亡（Dead）**。r16 起取代原"健康 / 缺水 / 枯萎"三形态模型。详见 §5.3。 |
| **收获（Harvested）** | 终局状态：全封闭结算时水量足够 → 收获。植物**保留占格**，参与终局计分（§6）；其所在 `land_region` 随即进入**锁定**状态（§5.6.1）。详见 §5.3 / §5.6。 |
| **死亡（Dead）** | 终局状态：全封闭结算时水量不足 → 死亡。植物立即移除；区域**不含任何收获植物**时，死亡空出的格可再次种植（§5.6.2 [提案]）。不参与计分。详见 §5.3 / §5.6。 |
| **区域锁定（Region Lock）** | 收获的附带效果：含收获植物的 `land_region` 被**锁定**——任何玩家（含收获者本人）不可再在该区域的任何格上种植，区域供水量 V_L **冻结**（不再参与后续水量变化），收获植物因此结构性免疫驱逐。详见 §5.6.1。 |
| **区域退种（Per-Region Refund）** | 种子退还以 `land_region` 为单位：同一次结算事件（闭合结算或驱逐）中，每位涉及玩家退还 **1 枚**该物种种子——**不论其拥有 / 损失多少株植物**（用户原话："退种子是一个联通的区域退一个，不是说每块地都退一个"）。详见 §5.4.1 / §5.6.2。 |
| **物种优先级（Species Priority）** | 树 > 花 > 草。当同一 `land_region` 内出现不同物种时，高优先级物种**驱逐**低优先级物种。详见 §5.4.1。 |
| **驱逐（Expelled）** | 被更高优先级物种赶走的移除方式：立即移除，并按**区域退种**原则退还种子（每位被驱逐的玩家 1 枚）。不算"死亡"，被驱逐的格立即空出。详见 §5.4.1。 |
| **同级竞争（Peer Competition）** | 同物种植物分属不同玩家且共存于同一 `land_region` 时的计分规则：数量多的一方独得该物种在该区域的全部得分，数量相同则平分。详见 §6.3。 |
| **自动扩张（Auto Expansion）** | 植物的被动传播机制：每当新地块放置后与某个已种植地块相邻、且两者土地连通（同属一个 `land_region`），该已种植地块上的植物会自动扩张到新地块上。不消耗种子、不占用玩家动作。详见 §5.4.2。 |
| **种植（Planting）** | 玩家放置完地块后可选的主动动作：只能在**当前玩家本回合刚放置**、未被植物占据且包含可种植土地的地形块上种下一株植物。其它历史地块不是主动种植目标。消耗 1 枚对应种类种子，规则详见 §5.8 / §7.2.2.A。 |
| **全封闭（Fully Closed）** | 土地块全封闭 = 该 `land_region` 的所有 land 边均已被对接。全封闭触发 §5.6 的死亡/收获结算（r16 起不再要求"关联水网也全封闭"）。详见 §5.6.1。 |

策划案旧名词继续沿用，包括：地块（Tile）、边口（Edge Port）、土地边、水口、空地边、土地块（Land Region）、土地群（Land Component）、水网（Water Component）、灌溉接点（Irrigation Link）、土地单位（Land Unit）。

## 2. 地块 5 维数据结构

### 2.1 数据形状（[已确认]）

一个地块用以下 5 个独立字段描述：

```text
Tile5D = {
    north: EdgeKind,
    east:  EdgeKind,
    south: EdgeKind,
    west:  EdgeKind,
    center: CenterKind
}
```

- `north / east / south / west` 是旋转方向上的固定指代，旋转仅改变其在棋盘上的朝向，不改变字段本身含义。
- `center` 不参与边缘匹配，但参与水源与植物归属结算。

### 2.2 边基础地形（[已确认]）

```text
enum EdgeBase:
    LAND    ; 含可种植土地边的边
    EMPTY   ; 草地 / 留白，无土地无水
    WATER   ; 标准水口
    RIVER   ; 河流（与水口并列的第四种基础地形）
    BANK    ; 河岸（仅河流地块持有；可对接 EMPTY 或 WATER；详见 §2.4.4）
```

**EdgeKind 的实际取值 = EdgeBase + 可选 IRRIGATION 修饰。**

```text
enum EdgeKind:
    LAND                          ; 土地边
    LAND_WITH_IRRIGATION          ; 含灌溉节点的土地边
    EMPTY                         ; 空地边
    WATER                         ; 标准水口
    WATER_WITH_IRRIGATION         ; 含灌溉节点的水口
    RIVER                         ; 河流（不允许带 IRRIGATION 修饰）
    BANK                          ; 河岸（仅河流地块持有；不允许带 IRRIGATION 修饰）
```

### 2.3 中心地形（[已确认]）

```text
enum CenterKind:
    CENTER_EMPTY    ; 中心是空地（草地、留白）
    CENTER_LAND     ; 中心是可种植土地
    CENTER_LAKE     ; 中心是湖泊（新增；等价于策划案里的"泉眼"）
    CENTER_RIVER    ; 中心是河流（新增；视觉/形状不同于湖泊，水量结算同等处理）
```

### 2.4 强制结构约束（[已确认]）

本节定义由中心地形、边基础地形、边修饰组合而成的合法地块形态。一块合法的 `Tile5D` 必须**同时满足** §2.4.1 – §2.4.6 的全部条款。

#### 2.4.1 IRRIGATION 修饰与中心地形的对应规则（[已确认]）

按 IR 修饰子类，给出各自合法的中心地形：

- **[已确认]** `WATER_WITH_IRRIGATION` 边所在的地块，其 `center` 必须为 `CENTER_LAND`。这是唯一允许水网跨界灌溉接口存在的位置；中心是 `EMPTY` / `LAKE` / `RIVER` 时该接口找不到 land 接收方，无效。
- **[已确认]** `LAND_WITH_IRRIGATION` 边所在的地块，其 `center` 必须为 `CENTER_EMPTY` 或 `CENTER_LAKE`：
  - 中心 `CENTER_EMPTY` 时，每条 land 边独立成块，该接口是 land 块单独的灌溉入口；
  - 中心 `CENTER_LAKE` 时，该接口跨越 land↔水网两域，**地块自动并入水网连通集合**（与 §3.3.1 中心 `CENTER_LAKE` 整体并入水网的规则一致，这里是带 IR 修饰的 LAKE 地块的触发条件重申）；
  - 中心 `CENTER_LAND` 时整块 land 区域已合并，再开 LAND 灌溉接口会自灌，配置无效；
  - 中心 `CENTER_RIVER` 见 §2.4.4 与 §2.4.5：河流地块不允许 IR 修饰。
- **[已确认 · 决策一览表]**

| 中心 | `WATER_WITH_IRRIGATION` | `LAND_WITH_IRRIGATION` | 是否自动入水网 |
| --- | --- | --- | --- |
| `CENTER_LAND` | ✓ | ✗ | 否（仅通过其水口边所属外部水网供电） |
| `CENTER_EMPTY` | ✗ | ✓ | 否（land 块自我接水，不入水网） |
| `CENTER_LAKE` | ✗ | ✓ | **是**（地块整体入水网） |
| `CENTER_RIVER` | ✗ | ✗ | 是（地块自身就是水网成员，IR 边不允许） |

#### 2.4.2 中心 = `CENTER_LAND` 时的 land 群约束（[已确认]）

- **[已确认]** 4 条 land 边（含 `LAND` 与 `LAND_WITH_IRRIGATION`）合并成一个**统一的 `land_region`**；中心 `CENTER_LAND` 本身属于该 `land_region`。
- **[已确认]** 由 §2.4.1 决策一览表可得：中心为 `CENTER_LAND` 的地块，IR 修饰只可能为 `WATER_WITH_IRRIGATION`，不可能出现 `LAND_WITH_IRRIGATION`。

#### 2.4.3 中心 = `CENTER_EMPTY` 时的 land 群约束（[已确认]）

- **[已确认]** 中心 = `CENTER_EMPTY` 的地块，4 条边中的所有 land 边**互相独立**，各占一个**独立的 `land_region`**——即使 4 条边全是 land，也算 4 个独立 land 区域，互相不连通。
- **[已确认]** 由 §2.4.1 决策一览表可得：中心为 `CENTER_EMPTY` 的地块，IR 修饰只可能为 `LAND_WITH_IRRIGATION`，不可能出现 `WATER_WITH_IRRIGATION`。

#### 2.4.3.5 中心 = `CENTER_LAKE` 时的地块约束（[已确认]）

- **[已确认]** 中心 `CENTER_LAKE` 的地块**本身即作为整体并入所连接的水网连通集合**（与 §3.3.1 一致）。
- **[已确认]** 由 §2.4.1 决策一览表可得：含 IR 修饰时只可能为 `LAND_WITH_IRRIGATION`，不允许 `WATER_WITH_IRRIGATION`；但当 `LAND_WITH_IRRIGATION` 出现在 `CENTER_LAKE` 地块上时，该地块在地块放下阶段即被强制并入水网连通集合（自动归属，不依赖外部水网连接；具体归属哪个水网由相邻水口/IR 边的连通性决定）。
- **[已确认]** `CENTER_LAKE` 地块上**不需要**任何 `LAND_WITH_IRRIGATION` 也照样入水网——IR 修饰是该地块跨界 land 灌溉接口的开关，不是入水网的必要条件。

#### 2.4.4 中心 = `CENTER_RIVER` 时的河流地块（[已确认]）

河流地块是本规则书新增的**专规类型**，必须同时满足下列全部条款：

- **[已确认]** 河流地块的 `center` 强制为 `CENTER_RIVER`。
- **[已确认]** 河流地块**至少含 1 条 `RIVER` 边**（让中心河道有出口），但允许 1–4 条。
- **[已确认]** 河流地块的边类型**只能取 `RIVER` 或 `BANK`**，**不允许**出现 `LAND` / `WATER` / `EMPTY` / 含 IRRIGATION 修饰的任何边。`BANK` 是专为河流地块新增的"河岸"地形（详见 §1 / §2.2）。
- **[已确认]** `RIVER ↔ RIVER` 拼接合法（同基础地形对接）；不允许 `RIVER ↔ WATER` 的直接拼接；`RIVER ↔ BANK` 也**不允许**直接拼接（详见 §9 #7）。
- **[已确认]** **`RIVER` 边与 `CENTER_RIVER` 中心都不贡献水源、不组成水网**——它们仅承担"全局唯一完整河流"的连通约束（详见本节末段全局约束条款）。水源贡献走 §4.1：河流地块的 `RIVER` 边 / `CENTER_RIVER` 中心都不命中任何水源档位（按 §4.1 第 4 档 0 点）。
- **[已确认]** 河流地块的 `BANK` 边可与外部水口（`WATER` / `WATER_WITH_IRRIGATION` 基础地形）**对接合法**，对接一旦发生：
  - 该 `BANK` 边被**永久改写为水渠**（详见 §1 / §4.1）：落地形式是 `water_rewrite_at` 字段标记原 `BANK` 边已被水口改写，**保留原 `BANK` 基础类型不动**，但语义上：
    1. 后续所有结算（拼接校验、连通性、水量、灌溉可达）按"水口边"对待；
    2. 该 `BANK` 边按 §4.1 第 5 档（水渠档）为**所在水网**额外贡献 **6 点**水源容量——这是 §4.1 唯一可以"对同一水网叠加获取"的档位（即**多个水渠边各算一份 6 点**，详见 §4.1）。
  - 一旦改写，该边失去 `BANK` 的所有特性（例如它不再与另一侧的 `EMPTY` 拼合法）。
- **[已确认]** 河流地块的 `BANK` 边与外部 `EMPTY` 边对接**合法且不发生改写**——这是 `BANK` 的"本职"对接（BANK ↔ EMPTY 同型合法）。双方保留各自的 `BANK` / `EMPTY` 基础类型，仅作视觉上的"河岸接空地"过渡。
- **[已确认 · 全局连通约束]** **游戏中所有 `RIVER` 边必须构成一条完整的连通河流**（一个 `River Component`，全局唯一）。禁止出现多个互不连通的河流群。任何让 `RIVER` 边落入孤立群的操作（无论放置、改写、扭转）都被规则拒绝——例如新地块的 `RIVER` 边如果会让全局 `RIVER` 集合分裂成 ≥2 个不连通子图，则该放置非法。**该连通约束独立于水网连通**：河流不进入水网连通集合（§3.3.1），仅约束 RIVER 边本身必须全局唯一连通。

#### 2.4.5 `RIVER` 边不允许 IRRIGATION 修饰（[已确认]）

- **[已确认]** `RIVER` 边不允许带 IRRIGATION 修饰。河流本身已经是水源元素，没必要再有"灌溉"标记。

#### 2.4.6 修饰互斥（[已确认]）

- **[已确认]** 同一条边不允许同时叠加两个修饰（目前也只有 IRRIGATION 一个修饰，未来若有新修饰，需保持互斥）。

## 3. 拼接机制

### 3.1 棋盘与旋转（沿用策划案 §4.1）

- **[已确认]** 地块由四条边构成：北、东、南、西；旋转以 90° 为单位；新地块必须至少与一张已有地块边对边相邻（不接受角碰角）。
- **[已确认]** 边界外侧不需要匹配；只有与已放置地块实际接触的边参与校验。

### 3.2 边口类型匹配（[已确认]）

拼接默认只看**边基础地形**，`IRRIGATION` 修饰不参与类型判定。本节共 5 种基础地形：`LAND` / `EMPTY` / `WATER` / `RIVER` / `BANK`。其中 **`BANK` 是专为河流地块新增的"河岸"地形**，对接规则独立于 `EMPTY` ——它可以同型对接 `EMPTY` 与 `WATER`。

| 接触边 | 是否合法 | 说明 |
| --- | --- | --- |
| `LAND` ↔ `LAND`（任一侧可带/不带 IRRIGATION） | 是 | 两侧土地加入同一连续土地群。 |
| `WATER` ↔ `WATER`（任一侧可带/不带 IRRIGATION） | 是 | 两侧水口在边中心点相接，加入同一水网。 |
| `RIVER` ↔ `RIVER` | 是 | 两侧河流连通，加入同一水网。 |
| `EMPTY` ↔ `EMPTY` | 是 | 地貌平滑相接，但不形成土地或水网。 |
| `BANK` ↔ `BANK` | 是 | 仅当两侧均为河流地块时出现（BANK 仅由河流地块持有），作河岸对接处理，不改写、不入水网。 |
| `BANK` ↔ `EMPTY` | **是**（`BANK` 的本职对接） | 河流地块的河岸边与外部空地边对接，**双方基础类型保留不变，不发生改写**，仅作视觉上的"河岸接空地"过渡。 |
| `BANK` ↔ `WATER` / `WATER_WITH_IRRIGATION` | **是 + 触发改写** | 仅当本方为河流地块、邻方为基础水口时才允许（即持有 BANK 的一方必须是河流地块）。对接瞬间该 `BANK` 边被**永久改写为水口**（落字段 `water_rewrite_at`，原 `BANK` 基础类型保留不动），后续所有结算（拼接校验、连通性、水量、灌溉）按"水口"对待。详见 §2.4.4。 |
| 任何其他不同的基础地形 | 否 | 该位置不能放置。 |

**显式约束：**
- `LAND_WITH_IRRIGATION` 与 `LAND` 互接 → **合法**（同属 `LAND` 基础地形）。
- `WATER_WITH_IRRIGATION` 与 `WATER` 互接 → **合法**。
- `LAND` 与 `WATER` 互接 → **不合法**，即便一侧带 IRRIGATION 也不行：IRRIGATION 仅在水源结算里起作用，不改变可拼接类型。
- `RIVER` 与 `WATER` 互接 → **不合法**：`RIVER` 边一律由河流地块持有，对侧也只能是 `RIVER` 边（详见 §2.4.4 与 §9 #7）。
- **`BANK` ↔ `RIVER` / `LAND` 仍不合法**：`BANK` 是河岸，只允许对接 §3.2 表格中明确列出的三类（`BANK` / `EMPTY` / 水口）。
- **`EMPTY` 边 ↔ 水口（`WATER` / `WATER_WITH_IRRIGATION`）整体仍不合法**——`BANK` 是河流地块的专属边类型，**非河流地块**的 `EMPTY` 边和水口对接**仍不合法**（防止规则被广泛滥用）。
- **`BANK` ↔ 水口的改写不可逆**：对接一旦合法且发生，该 `BANK` 边进入"已改写为水口"状态；与已改写边相对放置新地块时按"水口 ↔ 水口"处理；该 `BANK` 边的"原 BANK 身份"只在 UI / 历史日志中可见，不再参与拼接校验与连通集合计算。

### 3.3 拼接后的连通性刷新（[已确认]）

#### 3.3.1 水网连通性的构成（[已确认]）

本节正式定义"水网（Water Component）"的连通判定规则。任何满足下列条件之一的边/地块，并入同一个全局最大连通子图：

1. **[已确认]** 一条 `WATER` / `WATER_WITH_IRRIGATION` 边，与相邻地块同基础类型的水口边拼接后，两侧都加入水网集合。
2. **[已确认]** 任何含 `IRRIGATION` 修饰的边（不论基础是 `LAND` 还是 `WATER`），都**自动并入**连通到的水网集合——即"含灌溉节点"在结算时同等于一个水口接口。
3. **[已确认]** 中心是 `CENTER_LAKE` 的地块，整体并入所属水网集合。
4. **[已确认]** 河流地块**已改写的 `BANK` 边**（即水渠）按水口对待，归属到与对侧水口共属的水网集合；但 **`RIVER` 边与 `CENTER_RIVER` 中心不进入水网**——它们仅承担 §2.4.4 全局连通约束，与水网连通相互独立。详见 §2.4.4 与本节末段说明。
5. **[已确认]** `RIVER ↔ RIVER` 拼接**不进入水网连通集合**——仅维护 §2.4.4 的"全局唯一完整河流"连通约束，不在水网里产生容量贡献；水流不通过河流段本身流通，河流仅经由河流地块的"水渠边"间接与水网接口。

#### 3.3.2 land 群连通性的构成（[已确认]）

land 群（Land Component）的连通走另一套规则，与水网**互相独立**：

1. **[已确认]** 两条 `LAND` / `LAND_WITH_IRRIGATION` 边对接，且两侧地块的中心都是 `CENTER_LAND` → 两侧 `land_region` 合并为同一 `land_component`。
2. **[已确认]** 两条 `LAND` / `LAND_WITH_IRRIGATION` 边对接，但其中一侧地块中心是 `CENTER_EMPTY` → 两侧 `land_region` **不合并**（中心空地切断）。
3. **[已确认]** 即使 4 条 land 边接的是不同地块，只要每个地块的中心都是 `CENTER_EMPTY`，每条 land 边就属于**独立的** `land_region`——互不连通。

#### 3.3.3 跨界灌溉接口（[已确认]）

- **[已确认]** 含 `IRRIGATION` 修饰的边，作为"land 区域 ↔ 水网"之间的跨界接口：land_region 侧通过该边接收灌溉，水网侧通过同一条边供水。
- **[已确认]** 具体生效条件：
  - `LAND_WITH_IRRIGATION` 边所在的 `land_region` 标记"已被跨界灌溉"；
  - `WATER_WITH_IRRIGATION` 边所在的连通集合标记"已跨界供电"。
- **[已确认]** 单边含 IR（即一侧有 IR、另一侧是普通 `LAND` / `WATER`）也视作有效跨界接口，但只有"对侧也是 IR"时水才能真的流通（否则接口空对地不供电）。

### 3.4 中心地形不参与匹配（[已确认]）

- **[已确认]** 一块地块的 `center` 不会因为它接触的邻居是 `LAND` / `EMPTY` / `WATER` / `RIVER` 而合法或非法。中心只在水源与植物归属阶段起作用。
- **[已确认]** 一个 `CENTER_LAND` 地块可以与四向邻居全是 `EMPTY` 的地块正交相邻；中心土地的扩张由"边对边同型 land 边"驱动，不由中心地形决定。

### 3.5 拼接合法性伪代码（更新版）

```text
can_place(tile, coord, rotation) =
    rotated = rotate(tile, rotation)
    for each face f in {N, E, S, W}:
        neighbor = board[coord + face_offset]
        if neighbor is None: continue                          # 边界外不参与校验
        face_on_tile      = rotated.edge_at(face=f)
        face_on_neighbor  = neighbor.edge_at(face=opposite(f))
        k_tile = base_kind(face_on_tile)
        k_nb   = base_kind(face_on_neighbor)
        # 同基础类型：默认合法（包括 BANK↔BANK、BANK↔EMPTY、BANK↔WATER）
        if k_tile == k_nb: continue
        # 不同基础类型：唯一允许的拼接——河流地块的 BANK ↔ 水口基础类型
        if is_river_bank_water_pair(rotated, neighbor, f):
            mark_pending_water_rewrite(rotated, f)               # 把这条 BANK 边加入"待改写"集合
            continue                                            # 通过校验
        return false                                            # 其他不同基础类型一律拒绝
    return true

is_river_bank_water_pair(my_tile, neighbor_tile, face) =
    my_face = my_tile.edge_at(face=face)
    nb_face = neighbor_tile.edge_at(face=opposite(face))
    # 方向 A：我是河流地块 + 我的这条 BANK 边 + 邻方是水口基础类型
    cond_a = (my_tile.center == CENTER_RIVER
              and base_kind(my_face) == BANK
              and base_kind(nb_face) in {WATER, WATER_WITH_IRRIGATION})
    # 方向 B：邻方是河流地块 + 邻方那条 BANK 边 + 我方是水口基础类型
    # （覆盖"我方先放下水口地块，邻方河流地块"的场景）
    cond_b = (neighbor_tile.center == CENTER_RIVER
              and base_kind(nb_face) == BANK
              and base_kind(my_face) in {WATER, WATER_WITH_IRRIGATION})
    return cond_a or cond_b

# IRRIGATION 修饰不参与 can_place 判定，只参与水源结算。
# center 不参与 can_place 判定（除 §2.4.4 河流地块中心必 RIVER 这一项独立约束）。
# BANK ↔ EMPTY 与 BANK ↔ WATER 都在 §3.2 表格里被列为同型合法，不再走"特例"路径；
# 仅 "是否要永久改写" 由 is_river_bank_water_pair / mark_pending_water_rewrite 决定。
```

### 3.6 拼接后的事件伪代码（[已确认]）

地块放下后的事件钩子（基于本节 §3.3 的规则再写一遍实现顺序）：

```text

    # 1. 基础拼接校验（已通过 can_place；含 §2.4.4 河流地块 BANK↔水口这一对组合的同步改写标记）
    # 2. RIVER 全局连通校验
    if tile is RiverBlock:
        for each RIVER face of tile:
            ensure_river_global_connectivity()        # RIVER 必属唯一一条河流
    # 3. land 群合并
    merge_land_components_at(coord)                   # 中心 LAND 合并入相邻 land 群
                                                      # 中心 EMPTY 禁止合并
    # 4. water 群合并（含 IRRIGATION 跨界接口 + 河流地块已改写边）
    merge_water_components_at(coord)                  # 普通水口、IR 边、河流地块水口等价边一并入连通集合
    # 5. flush 河流地块的 BANK → 水口改写
    apply_river_block_water_rewrite(tile, coord)      # 把 can_place 阶段标记的 pending 永久写入 water_rewrite_at
                                                      # 此时 BANK 边才真正"语义上"成为水口边
    # 6. 灌溉可达集合
    recompute_irrigation_links_from(coord)            # 刷新 IR 跨界接口对 land_region 的可达性
    # 7. 触发 §4 水量结算
    schedule_water_balance_recompute()                # 仅当含 IR 边或 water 边接到水网时触发
    # 8. 物种冲突解决（§5.4.1）：本次合并涉及的 land_region 内若出现不同物种的植物，
    #    高优先级立即驱逐低优先级（移除 + 退还种子）
    resolve_species_conflicts_around(coord)
    # 9. 自动扩张（§5.4.2）：紧邻新地块、与其土地连通（同 land_region）的已种植地块，
    #    其植物自动扩张到新地块上（不消耗种子、不占用动作）
    auto_expand_plants_onto(coord)
```

## 4. 水网与供水

本章定义"水如何从水源点出发、经过水网、抵达 land 群并形成灌溉"的完整算法链。核心规则：

- **河流不再贡献水源、不再组成水网**——`RIVER` 边与 `CENTER_RIVER` 中心按 §4.1 第 4 档命中（P = 0），仅承担 §2.4.4 的"全局唯一完整河流"连通约束。
- **水渠（canal）成为新的水源机制**：河流地块的 `BANK` 边与外部水口对接后形成的"水渠边"，按 §4.1 第 5 档为**所在水网**贡献 **6 点**水源容量；多条水渠边对同一水网独立贡献，**可以获取多次**。

本章完整算法链：

```
单地块水源点数 P (§4.1)
  ↓ Σ 累加到水网
水网水源容量 S_W (§4.2)
  ↓ 水网直接灌给每个被灌溉 land_region（不分摊）
单 land_region 实际供水量 V_L = f(S_{K_1}, S_{K_2}, ...) (§4.4)
  ↓ 跨水网合并
死亡 / 收获判定：见 §5.5 / §5.6
```

### 4.1 单地块水源点数 P 与水渠点数（[已确认]）

每块地块对其所属水网 W 贡献一个**地块级**水源点数 P（按四档优先级取档、不叠加）；水网 W 还按"水渠边数量"独立累加一个**边级**水源点数 P_canal（详见本节末段）。两者在 §4.2 一起合并为 S_W。

#### 4.1.1 地块水源点数 P（按四档优先级取档）

| 优先级 | 满足条件 | 地块水源点数 P |
| ---: | --- | ---: |
| 1 | 中心是 `CENTER_LAKE`（未被本节档位提前命中） | **3**（= 1 + 2 的湖泊加成） |
| 2 | 含 `WATER` / `WATER_WITH_IRRIGATION` / `LAND_WITH_IRRIGATION` 之一，且地块内部确实能让水灌溉到 land（即中心 `CENTER_LAND` 或同地块存在 land 节点） | **1** |
| 3 | 完全无上述触发（包括只含 `RIVER` 边 / 中心 `CENTER_RIVER` 但无 WATER / LAKE 的情况） | **0** |
| 4 | 显式黑名单：`CENTER_RIVER` 中心、`RIVER` 边 | **0**（不贡献水源，与原"取档"无关；显式列出防止未来误把河流再算入） |

> 关键点：
>
> - **同地块只取一档**，按"中心 LAKE → 普通有水 → 0"优先级向上取首个命中档；中心 LAKE 单独一块没有水边也没灌溉节点时，第 1 档仍命中（中心 LAKE 是水网元素，本身就给 3 点）。
> - **河流档位为 0**——`RIVER` 边 / `CENTER_RIVER` 中心不贡献水源；它们仅承担 §2.4.4 全局连通约束。
> - 普通水地块若"水穿过地块但无法灌溉到 land"（如 `WATER` 地块 + 中心是空地/湖泊），第 2 档仍命中 1 点——水源贡献只看"是否能入水网"，不要求"是否灌溉到 land"。后者是 §4.5 的判定。

#### 4.1.2 水渠点数 P_canal（按边独立累加，**可获取多次**）

水渠（canal）是 §1 / §2.4.4 定义的"河流地块 `BANK` 边被外部水口对接后形成的永久改写边"。**每条水渠边**为**所在水网**额外贡献 **6 点**水源容量，**与地块级 P 无关，独立累加**：

| 边 | 贡献给所在水网的水源点数 P_canal |
| --- | ---: |
| 每一条被永久改写为水渠的 `BANK` 边（即 `water_rewrite_at` 中标记的边） | **6** |

> 关键点：
>
> - **每条水渠边独立贡献 6 点**，对同一水网可叠加——这是用户原文"可以获取多次"的具象语义：一块水网连接两条河流地块、每条河流地块有两条水渠边，则水渠贡献 = 4 × 6 = **24 点**。
> - 水渠点数是**边级**而非**地块级**：即使两条水渠边都在同一块河流地块上，仍按 2 份 6 点算。
> - 水渠点数的归属是**所在水网**（即该水渠边的对侧水口所属的水网），不是河流自身的全局连通集合——河流本身不组成水网。
> - 水渠点数与地块级 P **不叠加冲突**：地块级 P 算在水网里（按 §4.1.1），水渠点数也算在同一水网里（按 §4.1.2），两者一起贡献 S_W。

### 4.2 水网水源容量 S_W（[已确认]）

每个水网连通集合 W 的**水源容量** S_W 定义为该集合内**地块级 P** + **水渠边级 P_canal** 的总和：

```text
S_W = ( Σ { P_tile | tile ∈ W } )  +  ( Σ { P_canal | canal_edge ∈ W } )
```

> 关键点：
>
> - 一块地块只属于一个水网（连通集合划分是唯一的），不会重复计入。
> - 即使某地块按 §4.1.1 第 3 档命中（P = 0），它仍然属于该水网（只要它有水口边与水网连通）；它对 S_W 的贡献为 0 但仍参与连通分类。
> - 一条水渠边只属于一个水网（同一条边的对侧水口唯一归属一个水网集合），不会重复计入。
> - **水网是 §3.3.1 定义的最大连通子图**。`CENTER_LAKE` 地块按 §3.3.1 隐式入水网，按 §4.1.1 第 1 档给水网贡献 P。`CENTER_RIVER` 地块按 §3.3.1 **不**入水网（仅承担 §2.4.4 全局连通约束），所以即使它含水渠边，那些水渠边也按"对侧水口所在水网"独立贡献。
> - **[已确认]** S_W **不设上限**——单个水网可以无限积累水源容量（含多水渠边叠加）。

### 4.3 水网对每个被灌溉 land_region 直接灌 S_W（[已确认]）

水网 W 灌溉到的**每一个** `land_region` L，都**直接获得**该水网的全部水源容量 S_W：

```text
L.received_from_W = S_W
```

> **核心规则：水网供水率为 1——不引入"供水率"概念，对每个被灌溉 land 的供水量都是 S_W 满值**：
>
> - **不引入"供水率 R_W"概念**——水网不按任何比例分摊水量。每个被灌溉 land_region 拿到的就是 S_W 这个"满值"。
> - **不引入"灌溉覆盖 T_W"概念**——没有分摊，T_W 没有计算意义。
> - 同水网内所有被灌溉的 land_region **拿到的水量彼此相等**（都等于 S_W），不论它们各自与水网有几个 IR 接口——这就是"等量供水"的语义。
> - **S_W > 1 也无所谓**，每 land 单位需水按 §5 植物与归属章节的"植物水量需求"具体数值；多余水量不浪费但也不溢出到其他 land。

### 4.4 单 land_region 的实际供水量 V_L（[已确认]）

一个 `land_region` L 实际接收到的总水量由其连接的所有水网 K_1, ..., K_n 的 S 值**直接求和、无封顶**：

```text
V_L = Σ S_{K_i}
```

> **关键点**：
>
> - **[已确认]** 每个水网对 L 的贡献是独立的 S_{K_i}（每条水网灌"一整份"给 L，不分摊）。
> - **[已确认]** 合并算子 ⊕ = **sum 无上限**——多水网交汇的 land_region 会获得所有接入水网的水量总和，成为"超级沃土"。

### 4.5 灌溉接点的语义边界（[已确认]）

确认"什么算成功灌溉、什么不算"——本节对应"同一 land_region 对同一水网只算 1 次"的核心规则：

- **[已确认]** "成功灌溉" = `land_region` L 通过至少一个 IR 接口接通水网 W（§3.3.3 跨界接口判定）。此时 L 直接获得 S_W（按 §4.3）。
- **[已确认]** **同一 `land_region` 对同一水网只算 1 次**：即使 L 对水网 W 有多个 IR 接口（例如地块 a 同时含一条 `WATER_WITH_IRRIGATION` 边和一条 `LAND_WITH_IRRIGATION` 边都通向水网 W），L 从 W 拿到的水量仍是 S_W，**不会变成 N × S_W**。
- **[已确认]** **不同 `land_region`（即使在同一地块上，例如中心 EMPTY 时每条 land 边各算一块）独立计数**：每块 land_region 都各自从其连接的水网拿到完整的 S_W。
- **[已确认]** "水穿过但不灌溉"的情形（普通 `WATER` 地块、中心非 `CENTER_LAND`）不构成 IR 接口——水从这块地穿过但没有 IR 跨界接口，因此 L 不算被该水网灌溉到。
- **[已确认]** 没有 IR 接口的水口边（普通 `WATER`）只参与水网连通（§3.3.1），不参与灌溉。
- **[已确认]** **水渠边（`water_rewrite_at` 标记的 `BANK` 边）的对接关系**：水渠边算作水口，但**它的对接侧是普通水口，不是 land**——水渠边不直接给 land 灌水；它给所在水网贡献 P_canal，所在水网再通过其普通 IR 接口把 S_W 灌给 land。这就是"水渠通过水网"间接灌溉 land 的完整链路。

> 枯萎与恢复的判定不在本章——统一由 §5.6 / §5.7 给出完整算法。

## 5. 植物与归属

本章定义"每位玩家拥有的种子如何在游戏过程中种植、自动扩张、驱逐竞争、闭合结算与计分"的全套规则。

> v0.1 策划案里"植物"仅作为标签；本章将其落地为有三种需水量、可结算的对象。
>
> **r16 重构要点**：①植物放置统一为单一"**种植**"动作——可在**任意**未被植物占据的地形块上种，不再区分"扩张 / 种植"两个动作，主动扩张取消，改为**自动扩张**（§5.4.2）；②**每格一株**——已被任何植物（不论归属）占据的地形块不能再被选择；③缺水不再有可逆中间形态——水够不够推迟到土地块全封闭时一次性判定，结果只有**收获**与**死亡**两种，两者都退还种子；④新增**物种优先级与驱逐**（§5.4.1）与**同级竞争计分**（§6.3）。

> **r16.2 修订**：主动种植目标由历史任意空置地块收窄为**当前玩家本回合刚放置**的地块；其它棋盘地块不可触发种植悬停、菜单或点击动作。自动扩张（§5.4.2）不受此限制。

### 5.1 玩家、种子、地块的关系（[已确认]）

- **[已确认]** 每位玩家拥有自己**独立**的种子集合：集合内三种植物（草 / 花 / 树）并存，玩家可按 §7 节奏消耗种子种植（详见 §7，本章仅描述植物本身的规则）。
- **[已确认]** 玩家在放置植物时只能从自己的种子集合里取；不允许借种、换种、共用。
- **[已确认]** 种子是**种植时消耗**、**结算事件时按区域退还**的资源——种植时扣 1 枚对应种类种子（§5.8 / §7.2.2）；退还以 `land_region` 为单位（**区域退种**）：§5.6 全封闭结算或 §5.4.1 驱逐时，每位涉及玩家退还对应种类种子 **1 枚**——不论其在区域内拥有 / 损失多少株（用户原话："退种子是一个联通的区域退一个，不是说每块地都退一个"）。未发生结算事件的 `land_region` 上的植物不退还种子（退还触发器只有全封闭结算与驱逐两类）。
- **[已确认]** **多土地地块一次种满**（用户原话："多土地地块的话，一次性就是全部都种植"）：中心 `CENTER_EMPTY`、含多条互不连通 land 边的地块（§2.4.3）同时横跨多个 `land_region`；在其上种植（或被自动扩张）时，**一次动作、消耗 1 枚种子，同时占据该格全部 `land_region`**——每个区域各落 1 株同主同种植物，之后每个区域**独立**参与闭合结算、计分与退种。该格"空出可再种"的条件 = 其全部所属区域中的植株均已不在（死亡 / 驱逐）。
- **[已确认]** **每格一株**：同一地形块（即同一个 Tile5D 实例，对应棋盘上一格）上**最多只能存在一株植物**——不分物种、不分玩家。已被任何植物占据的地形块，不能再作为种植目标，也不会再被自动扩张选中（§5.4.2）。该限制与"土地块（`land_region`）"是不同层级：
  - "地形块（Tile）"= 棋盘上一格，由 5 维结构描述（§2）；
  - "土地块（Land Region）"= 由若干地形块的 land 边围成的连通区域（§3.3.2）。
- **[已确认]** **物种/玩家二元归属**：每株植物 `p` 同时绑定两个属性——`p.species ∈ {GRASS, FLOWER, TREE}` 与 `p.owner ∈ Players`。归属由种植动作（§5.8 / §7.2.2.A）显式指定，不存在"自动归属"或"按地块颜色归属"。
- **[已确认]** 一个 `land_region` 内可以有**多株**植物，分别种在不同地形块上；只要这些地形块都属于同一 `land_region`，它们共享水源（按 §4.3）。由于 §5.4.1 的驱逐规则，**任一时刻一个 `land_region` 内至多存在一个物种**——但同物种可以分属多个玩家（同级共存，计分见 §6.3）。
- **[已确认 · r16.2]** 种植目标 = **当前玩家本回合刚放置**且满足 §5.8 前置检查的地形块；历史地块不因空置、连通或归属而成为目标。除这一时序限制外，不要求与自己已有植物相邻或同区域。
- **[已确认]** 主动扩张动作**取消**——植物在地块间的传播由 §5.4.2 的**自动扩张**机制承担。

### 5.2 三种植物与水量需求（[已确认]）

| 植物 | 每地块需水量 `need` | 数量级 | 战略定位 |
| --- | ---: | --- | --- |
| **草（Grass）** | **0.5** | 低 | 门槛最低的"基底植物" |
| **花（Flower）** | **1** | 中 | 标准植物 |
| **树（Tree）** | **2** | 高 | 门槛最高的"主力植物" |

> 关键点：
>
> - `need` 只在 **§5.6 全封闭结算**时使用：结算时按 §5.5 分配水量，分配到 `need` 的植物**收获**，分配不到的**死亡**。闭合结算之前，水量是否足够**不产生任何规则效果**（用户原话："如果水不够，这个植物就会死亡，但这个死亡不是立即结算的，它要在当前地块完全闭合之后才会去计算"）。
> - `need` 是**单地块**需水量（用户原文："每一个地形块上的草需要 0.5 水源"），与 §4 的 S_W / V_L 都是同一量级——本规则书统一以"水源点数"为度量，不引入分数。
> - **同一地块最多一株植物**（§5.1）：一格不会出现多株植物叠加耗水；一个 `land_region` 的总需水 = 区域内所有植物的 `need` 之和。

### 5.3 植物状态（r16 重构）

任意时刻，每株植物 `p` 处于下列三种状态之一：

| 状态 | 含义 | 是否终局 | 进入条件 |
| --- | --- | --- | --- |
| **存活（Surviving）** | 正常生长，占格 | 否，可转为收获 / 死亡 | 种植 / 自动扩张成功后即进入；闭合结算前的唯一常态 |
| **收获（Harvested）** | 闭合结算时水量足够 | **是** | §5.6 闭合结算：分配水量 ≥ `p.need` |
| **死亡（Dead）** | 闭合结算时水量不足 | **是** | §5.6 闭合结算：分配水量 < `p.need` |

> 关键点：
>
> - **[已确认 · r16 变更]** **缺水不再是可逆中间形态**——r15 及之前的 HEALTHY / WATER_SHORT / WITHERED 三形态模型废弃。闭合结算之前，即使区域当前供水量不足，植物也**保持存活**，不产生任何即时后果（视觉上可表现蔫萎，但不影响规则状态）。
> - **[已确认]** **死亡只在全封闭结算时判定**——用户原话："这个死亡不是立即结算的，它要在当前地块完全闭合之后才会去计算"。
> - **[已确认]** **收获与死亡都会退还种子**——用户原话："任何这两种都可以去把这个植物回收种子"。
> - **[已确认]** **死亡之后该格空出**——可以被再次种植；**收获之后该格仍被这株植物占着**——不可再种植，植物保留到终局并参与计分（§6）。
> - 另有一种独立于状态的**移除方式：驱逐**（§5.4.1）——被更高优先级物种赶走。驱逐不是状态，是"立即移除 + 退还种子"的过程；被驱逐的格立即空出。

### 5.4 物种优先级、驱逐与自动扩张（r16 新增）

#### 5.4.1 物种优先级与驱逐（[已确认]）

- **[已确认]** 物种优先级：**树 > 花 > 草**。
- **[已确认]** **触发时机**：任何原因导致同一 `land_region` 内出现**不同物种**的植物时，立即按下述规则解决——包括：
  1. 玩家把植物**直接种进**已含有其他物种植物的土地块；
  2. 后续拼接地块使**两个各有植物的土地块连通**（用户原话："可能存在两个玩家占领的地，在后面拼接地块时连通了"）；
  3. 自动扩张把植物带进含有其他物种的区域。
- **[已确认]** **处理**：该 `land_region` 内只保留**最高优先级物种**的植物；更低优先级物种的植物被**驱逐**——**立即移除**，并按**区域退种**原则退还种子：每位被驱逐植物的玩家退 1 枚该物种种子（不论其被驱逐多少株，§1"区域退种"）。
- **[已确认]** **自己的高级植物同样会驱逐自己的低级植物**（用户原话："自己的植物也会赶走自己的植物"）——驱逐只看物种优先级，不看归属；被驱逐者的种子退还给其原主（哪怕就是执行驱逐的玩家自己）。
- **[已确认]** **同级不驱逐**：同物种的植物（不论同主异主）共存于同一区域时互不驱逐；跨玩家的同级共存按 §6.3 同级竞争计分。
- **[已确认]** 推论：任一时刻，一个 `land_region` 内至多存在一个物种。
- **[已确认]** 被驱逐**不算死亡**——驱逐立即执行、立即移除、立即退种；死亡则延迟到全封闭结算时才判定（§5.3）。
- **[已确认 · r16.1]** **收获植物不会被驱逐**——收获使其所在区域进入锁定状态（§5.6.1）：区域不可再种植、也已闭合无法通过拼接引入新地块与新物种，结构上不可能有异物种进入。这是"收获 = 落袋为安"的保证。

#### 5.4.2 自动扩张（[已确认]）

- **[已确认]** 植物不再需要玩家主动扩张——用户原话："植物不需要主动扩张，而是自动扩张，当有相邻的地块和这个已经种过植物的地块相邻时，植物会自动往新的地块上扩张"。
- **[已确认]** **触发**分为两个事件：
  1. 每当一张新地块被合法放置后，若它通过**土地边**与某个已含有植物的 `land_region` 连通，且它与该区域中某个**已种植地块直接相邻**，则该已种植地块上的植物**自动扩张到新地块上**；
  2. 每次玩家主动种植成功后，刚种下植物的地块会向所有**直接相邻、土地真正连通且尚未被植物占据**的既有地块各扩张一株同主、同种植物。
- **[提案]** **实施细则**（当前默认值，调整前应同步本节）：
  1. **不消耗种子、不占用玩家动作**——自动扩张是放置或主动种植事件的被动结果，种子余量为 0 也能触发；
  2. 仅**直接相邻**的地块触发——新地块经由无植物的中间格接入某区域时，不发生跨格扩张，该中间格保持空置；主动种植同样只从本次种植格向四邻格传播，不会在同一次事件中递归继续扩张；
  3. 新地块无可种植土地、或与已种植地块之间没有土地连通（仅水口 / 空地相接）时，不触发；
  4. 新地块同时与多个已种植地块相邻时：不同物种按 §5.4.1 优先级裁决（高优先级先占）；同物种多主时按**种植顺序先者占**（§5.8 种植顺序字段）；
  5. 自动扩张在放置事件内**立即结算**（§3.6 步骤 9），早于当前玩家的种植动作——即：你刚放下的地块若紧邻对手的已种植地块，可能先被对手的植物自动占据。
  6. **[已确认 · r16.1]** 新地块为多土地地块（§5.1）时，自动扩张**一次覆盖其全部 `land_region`**——每区域各落 1 株，与种植动作同规格（锁定区域因已闭合无法与新地块产生土地连接，此情形实际不会出现）。
- **[已确认]** 自动扩张产生的新植物进入**存活**状态；若扩张使不同物种进入同一区域，按 §5.4.1 立即驱逐。

### 5.5 闭合结算时的水量分配（r16 简化）

> r15 的"草优先 → 花树对半 → 互相补给"跨物种分配算法随驱逐规则失效——§5.4.1 保证一个 `land_region` 内至多一个物种，水量分配退化为**同物种多株植物分享 V_L**。

全封闭结算时，`land_region` L 的供水量 V_L（按 §4.4）按下述规则分配给区域内每株植物：

```text
# 输入：land_region L 的供水量 V_L，以及 L 上所有植物（按种植顺序排序）
# 输出：每株植物的 alloc 标记（true → 收获，false → 死亡）

for each plant p on L (按种植顺序):
    if V_L >= p.need:
        V_L -= p.need
        p.alloc = true          # → 收获
    else:
        p.alloc = false         # → 死亡
    # 水量按整棵满足（round-down）：分配不到整份 need 的植物死亡，
    # 剩余水量不拆分、不进位，继续尝试下一株
```

> 关键点：
>
> - **[已确认]** **水量按整棵满足（round-down）**——不存在"半满足"：一棵植物要么拿到完整的 `need`（收获），要么拿不到（死亡）。例如 V_L = 2.5 且区域内有 3 棵花时，前 2 棵收获、第 3 棵死亡。
> - **[提案]** 同物种多主争夺有限水量时按**种植顺序先者先得**；若未来希望其他顺序（如按玩家轮流分配），需修改本节。
> - **[已确认]** V_L = 0（区域没有任何外部水流供给）时，区域内所有植物在闭合结算时**全部死亡**——这落实用户原话"种在土地上的植物需要外部的水流才能存活"。

### 5.6 全封闭与死亡/收获结算（r16 重构）

> **本节是 §5.3 收获 / 死亡两个终局状态的正式入口**，同时也是**退还种子的触发器**。本节采用两阶段流程：**阶段 A 死亡/收获判定** → **阶段 B 统一退还种子**（死亡移除、收获保留）。

#### 5.6.1 全封闭定义（[已确认]）

- **[已确认]** "**土地块全封闭**"：一个 `land_region` L 的所有 `land` 边均已被其它已放置地块的同型 land 边对接——L 不会再扩张（即无法再拼接新的 land 地块）。
- **[已确认 · r16 变更]** 全封闭结算的触发条件**仅需土地块全封闭**——r15 中"关联水网也须全封闭才升级枯萎"的前置条件随三形态模型一并取消。水量是否足够，以**结算时点**的区域实际供水量 V_L（§4.4）为准；结算后再接入新水网也不会复活已死亡的植物。
- **[已确认]** 全封闭是结算时点的瞬时状态，每次结算时由规则重新判定。
- **[已确认 · r16.1]** **收获锁定区域**（用户原话："植物已经收获了的话，这个区域都是这个植物了，别人也没有地方可以种植了，包括水量也不会再减少"）：闭合结算中产生**收获**植物的 `land_region` 随即进入**锁定状态**——
  1. **禁种**：任何玩家（含收获者本人）不可再在该区域的任何格上种植（§5.8 检查 #4）；
  2. **水量冻结**：区域供水量 V_L 不再参与后续任何水量变化——水网后续增长、水渠改写均不影响已锁定区域；
  3. **免疫驱逐**：锁定区域不可能再进入新物种，收获植物结构上不可被驱逐（§5.4.1）。

  仅含死亡植物（或无植物）的闭合区域**不锁定**——死亡空格可再种植（§5.6.2 [提案]），再结算时水量按结算时点的 V_L 现值（未锁定，水网后续增长可以生效）。

#### 5.6.2 全封闭结算流程（[已确认]）

每次结算时（结算时机见 §7.2.3），按下述两阶段顺序处理每个新闭合的 `land_region` L：

```text
on_settle_land_region(L):
    if not (L is land_closed): return   # 仅 land 封闭才走本流程；未封闭跳过

    # 阶段 A: 死亡 / 收获判定（水量按 §5.5 分配）
    allocate_water_by_planting_order(L)         # §5.5：按种植顺序整棵满足
    for each plant p on L:
        if p.alloc:  p.state = HARVESTED        # 水量足够 → 收获
        else:        p.state = DEAD             # 水量不足 → 死亡

    # 阶段 B: 统一退还种子（收获与死亡都退，按区域退种）
    for each owner o with plants on L:
        refund_seed(o, species_of(L), 1)        # 每位玩家 1 枚——不论其株数
    for each plant p on L:
        if p.state == DEAD:
            remove(p)                           # 死亡：立即移除
        # 收获：保留占格，植物保留到终局并参与 §6 计分
    if any plant on L is HARVESTED:
        lock_region(L)                          # 区域锁定：禁种 + V_L 冻结（§5.6.1）
```

> 关键点：
>
> - **[已确认]** **收获与死亡都退还种子**——用户原话："完全闭合之后，植物有两种情况，一种是死亡，一种是收获，任何这两种都可以去把这个植物回收种子"。
> - **[已确认 · r16.1]** **退还按区域计**——用户原话："退种子是一个联通的区域退一个，不是说每块地都退一个"：每次闭合结算中，每位在区域内拥有植物的玩家退 **1 枚**该物种种子（区域至多一个物种，物种无歧义），与株数无关——种 5 株和种 1 株都只退 1 枚。多土地地块（§5.1）的植物横跨 N 个区域时，每个区域闭合各退 1 枚。
> - **[已确认]** **收获 → 格仍被占 + 区域锁定**：收获植物保留在原地继续占格到终局计分；其所在区域随即锁定（禁种 + V_L 冻结，§5.6.1）。
> - **[已确认]** **死亡 → 植株移除**：多土地地块须其全部所属区域的植株都已死亡 / 被驱逐后，该格才真正空出可再种（§5.1）。
> - **[提案 · r16.1 收窄]** **已闭合区域的再种植**：仅当闭合区域内**不含任何收获植物**（即全部死亡或无植物、未锁定）时，死亡空出的格仍可作为种植目标；新种植物在**下一个结算窗口**立即按本节流程单独结算（§7.2.3），水量按结算时点的 V_L 现值（区域未锁定，水网后续增长可以生效）。
> - **[已确认 · r16 变更]** r15 的"阶段 A 升级枯萎（需水网也全封闭）"取消——不存在枯萎状态；阶段 A 现在是死亡/收获判定。

### 5.7 游戏结束结算（r16 重构）

> 游戏结束的具体触发条件（地形牌堆抽完且放置完）见 §7.3。r16 下**不存在"终局缺水升级枯萎"步骤**——状态模型只有存活 / 收获 / 死亡，已闭合区域在主循环持续结算（§7.2.3）中已全部处理完毕。

游戏结束时刻：

```text
on_game_end():
    # 已闭合土地块：已在 §7.2.3 持续结算中处理（收获保留占格 / 死亡移除）——无需重复
    # 已闭合区域内仍在存活状态的植物（如终局前一回合刚种植、尚未结算的）：
    #     补跑一次 §5.6.2 结算，再进入计分
    # 未闭合土地块：植物保持存活状态，直接进入 §6 计分（花 / 树减半，§6.5）
    score_all()        # 详见 §6
```

> 关键点：
>
> - **[已确认]** 终局**不退还**未闭合区域的种子——种子退还的唯一触发器仍是全封闭结算（§5.6）；未闭合区域的存活植物带着"未退还的种子"直接进入计分。
> - **[已确认]** 未闭合区域的存活植物参与计分，但花 / 树按 §6.5 减半。
> - **[已确认]** 死亡与被驱逐的植物已从棋盘移除，自然不参与计分。

### 5.8 种植合法性与种植顺序（r16 重构）

- **[已确认]** **种植合法性前置检查**（在扣种子之前执行，失败则动作整体作废，不消耗种子、不留痕迹）：
  1. **[已确认 · r16.2]** 目标格 `t` 是**当前玩家本回合刚放置**的地块；历史地块一律不可作为主动种植目标；
  2. 目标格 `t` **包含可种植土地**（`CENTER_LAND` 中心，或属于某个 `land_region` 的 land 边所在格）；
  3. 目标格 `t` 上**没有任何植物**——不分物种、不分玩家（用户原话："不能选择已经种植了植物的地块，不论是自己的还是别人的"）；
  4. 玩家对应物种种子 ≥ 1；
  5. **[已确认 · r16.1]** 目标格 `t` 所属的**每一个** `land_region` 都**未锁定**（§5.6.1）——任一所属区域含收获植物即整格不可种植（用户原话："植物已经收获了的话，这个区域都是这个植物了，别人也没有地方可以种植了"）。

  五条之外**无任何限制**——不要求与自己植物相邻、不要求与自己植物同区域、不要求区域无主；但必须满足“本回合刚放置”。
- **[已确认]** 种进已有其他玩家（或自己）植物所在的 `land_region` 是**合法**的——只要目标格本身无植物。若引入了该区域当前物种之外的新物种，将按 §5.4.1 **立即触发驱逐结算**（新种的低级植物会被立即移除并退种）。
- **[已确认]** 新种植的植物进入**存活**状态；其收获 / 死亡在所在土地块全封闭结算时判定（§5.6）。
- **[已确认 · r16.1]** **多土地地块一次种满**（§5.1）：目标格横跨 N 个 `land_region` 时，一次种植在其全部所属区域各落 1 株同主同种植物，**共消耗 1 枚种子**；每个区域独立闭合结算、独立计分（§6.2"多次计算"）、独立退种（§5.6.2）。
- **[提案]** **种植顺序字段**：每次种植 / 自动扩张写入全局顺序表 `(plant, order)`。当前消费点：①§5.5 同物种多主分水排序；②§5.4.2 自动扩张的同物种多主裁决。其余场景（计分、胜负）不消费。
- **[已确认]** 本章不规定种植节奏、次数限制——这些是 §7 的范畴（每回合最多 1 次）。

## 6. 计分与胜负

> 本章基于用户原话："每一个玩家所有健康的植物中，每有一格土地块的草算1分、花2分、树4分（如果同一地形块内有多个土地块，多次计算），游戏结束时，分数最高获胜"。
>
> **r16 更新**：计分对象改为"**收获**的植物 + **未闭合区域仍存活**的植物"；新增**同级竞争**计分（§6.3）；每格一株后不再有同格多物种叠加。

### 6.1 计分公式（[已确认]）

每位玩家 P 的最终得分 `S(P)` 按下列公式计算：

```text
S(P) = Σ_{L ∈ land_regions}  Σ_{p ∈ plants(P) ∩ L, p ∈ scoreable(L)}
         weight(p.species) × peer(p) × multiplier(L, p.species)

scoreable(L) = 收获（HARVESTED）状态的植物
             ∪ （L 未封闭时）仍处于存活（SURVIVING）状态的植物
peer(p)      = §6.3 同级竞争修正（独得 = 1；平分 = 1/n；落败 = 0）
multiplier   = 1.0（L 已封闭）
             | 草 1.0 / 花、树 0.5（L 未封闭，§6.5）
```

其中物种权重表：

| 物种 | 单棵得分 `weight` | 备注 |
| --- | ---: | --- |
| **草（GRASS）**  | **1** | 基数种，最低门槛 |
| **花（FLOWER）** | **2** | 标准种 |
| **树（TREE）**   | **4** | 主力种，最高门槛 |

> 计分对每位玩家**独立计算**——按 `p.owner` 归属到对应玩家的总分。

### 6.2 计分维度（[已确认]）

- **[已确认]** **计分单位 = 单株植物**——收获状态的植物按全额计分；未闭合区域仍存活的植物按 §6.5 修正后计分。
- **[已确认]** **每格一株**（§5.1）——一格至多一株植物，不存在同格多物种叠加。
- **[已确认 · r16.1]** **多土地地块"多次计算"**（§5.1）——横跨 N 个 `land_region` 的植物，在其每个所属区域各按该区域的 multiplier 与同级竞争裁决**独立计分一次**：每格一株，但一格可因横跨多区域而贡献多份权重（原策划案"如果同一地形块内有多个土地块，多次计算"的落地）。
- **[已确认]** **死亡与被驱逐的植物不参与计分**——它们已从棋盘移除；被驱逐的格可以被再次种植。
- **[已确认]** **收获植物必然位于已封闭区域**（收获由封闭结算产生），multiplier 恒为 1.0。
- **[已确认]** **不计地块数、land_region 数**：计分 = 得分植物数 × 物种权重 × 修正因子；与植物所在的 land_region 数量无关、不与 tile 数挂钩。
- **[已确认]** **计分只在终局触发一次**——不存在"中途计分"或"得分阶段性累加"。
- **[已确认]** 计分与植物的"种植时间 / 种植顺序"无关——只看终局时的物种与状态（同级竞争的株数比较除外，§6.3）。

### 6.3 同级竞争（r16 新增）[已确认]

> 用户原话："如果两个同级的话，不会赶走，则在最终闭合算分时双方平分分数。如果某一方的同级的植物数量比另一方多，则这一方获得所有分数，另一方不得分。"

当同一个 `land_region` 内、**同一物种**的植物分属两位玩家时（§5.4.1 同级不驱逐），终局计分按下列规则裁决该物种在该区域的得分：

| 局面 | 结果 |
| --- | --- |
| 一方该物种株数 **严格多于** 另一方 | **多的一方独得**该物种在该区域的全部得分；另一方该物种 **0 分**（其植物虽留在场上、即使已收获，也不得分） |
| 双方该物种株数 **相同** | 双方**平分**该物种在该区域的得分——同物种同权重，等价于各自按自己的植株正常计分 |

- 判定按 `(land_region, species)` 二元组独立进行——不同区域、不同物种互不影响。
- **[提案]** 未闭合区域内的同级竞争同样适用，作用于**减半后**的分值（§6.5）。
- **[待确认]** 3 人以上对局中"多方并列最多"的处理——当前默认按双人规则描述（本游戏默认 2 人）。
- **[提案]** 奇数分平分（如双方各 1 棵草、区域已封闭 → 总分 1 分对半 = 0.5）当前**允许出现 0.5 分**；若要求整数分需另行设计。

**示例**：

> P1 与 P2 的花共存于同一个已封闭土地块：P1 有 2 棵、P2 有 1 棵 → P1 独得 (2 + 1) × 2 = **6 分**，P2 得 **0 分**（P2 的花虽收获且占格，但不计分）。
> 若双方各 1 棵 → 各得 **2 分**。

### 6.4 胜负判定（[已确认]）

游戏结束时（§7.3）按下列顺序裁决：

1. **[已确认]** **确认计分对象就绪**（§5.7）——已闭合区域结算完毕，未闭合区域保持存活状态；
2. **[已确认]** **再按 §6.1 计算每位玩家得分**（含 §6.3 同级竞争、§6.5 封闭修正）；
3. **[已确认]** **分数最高的玩家获胜**——按用户原话"游戏结束时，分数最高获胜"。
4. **[已确认]** **平局破平链**（同分时按下列顺序逐项比较，直到分出高下）：
   1. **收获 / 存活的树数量**多者胜（只看棵数，不看权重）；
   2. **封闭土地块中的得分**多者胜（即该玩家在 `land_closed` 的 land_region 上、收获植物的修正后得分之和——也就是没被 §6.5 减半的那部分得分）；
   3. **收获 / 存活的花数量**多者胜；
   4. **收获 / 存活的草数量**多者胜；
   5. 以上全部仍平 → **并列胜出**。

> 关键点：
>
> - 胜负**不依赖**状态转变历程——只看终局状态（收获 / 存活）。即使某株植物"曾经存活于水量充裕的区域、后来区域水网被改接"，只要它到终局仍以收获或存活状态留场，就计分。
> - 胜负**不依赖**地块归属——只看"哪个玩家拥有这株植物"。地块归属与玩家拥有是两件事（详见 §5.1）。

### 6.5 封闭与未封闭 land_region 的算分修正（[已确认]）

> 基于用户原话："游戏结束时，如果某个土地块没有封闭，则其中所有健康的花和树得分减半"。

#### 6.5.1 修正公式（[已确认]）

§6.1 的基础计分公式在终局按本节规则修正——引入 land_region 的封闭状态作为修饰因子：

```text
S(P) = Σ_{L ∈ land_regions}  Σ_{p ∈ plants(P) ∩ L, p ∈ scoreable(L)}  weight(p.species) × peer(p) × multiplier(L, p.species)

multiplier(L, species) = {
    1.0    if L is land_closed (土地块封闭)
    1.0    if species == GRASS  (草不参与减半)
    0.5    otherwise           (未封闭 land_region × 非草 → 减半)
}
```

> **关键点**：
>
> - **"土地块没有封闭"** 在本规则书里特指 `land_region` L 的 land 边**未**全部被对接——即 L 仍然存在至少一条可拼接的 land 边（L 不是 `land_closed`），水网的封闭状态**不影响**本判定。
> - **只有花（FLOWER）和树（TREE）参与减半**——草（GRASS）不减半。这是用户原话"所有健康的花和树得分减半"的精确落地。
> - 减半**针对单株植物**——每株满足"未封闭 land_region × 存活 × 花/树"的植物独立减半。
> - 减半的判定**只发生在终局计分时**——闭合结算过程（死亡/收获判定、退还）都**不**受减半影响。
> - 收获植物必在已封闭区域（multiplier = 1.0），减半仅作用于**未闭合区域的存活植物**。

#### 6.5.2 与既有规则的耦合（[已确认]）

- **[已确认]** **与 §5.6 全封闭结算独立**：§5.6 决定"哪些植物以什么状态留在场上"（收获保留 / 死亡移除），本节只对**未闭合区域**的存活植物打折——两条互不替代。
- **[已确认]** **与 §5.7 终局结算的关系**：终局不对未闭合区域做死亡/收获判定、也不退还种子；这些区域的存活植物以"未减半前的状态"进入 §6，由本节统一减半。
- **[已确认]** **与 §6.4 平局处理的关系**：平局判定基于"修正后得分"（即经过本节减半 + §6.3 同级竞争处理后的最终 `S(P)`）；不是基础分。

#### 6.5.3 公式示例（[已确认]）

> **示例**：玩家 P 拥有 3 株得分的花（均存活），分布在 3 个 land_region 上：A 封闭（×1.0）、B 未封闭（×0.5）、C 未封闭（×0.5）。
>
> - P 在 A 上的花：1 株 × 2 × 1.0 = 2 分；
> - P 在 B 上的花：1 株 × 2 × 0.5 = 1 分；
> - P 在 C 上的花：1 株 × 2 × 0.5 = 1 分；
> - 该 3 株花的总贡献 = 2 + 1 + 1 = 4 分（若全封闭 = 6 分，未封闭的情况下掉了 2 分）。
>
> **示例**：玩家 P 在一个未封闭的 land_region L 上有 1 株草 + 1 株花 + 1 株树（均存活）。
>
> - 草：1 × 1 × 1.0 = 1（草不减半）；
> - 花：1 × 2 × 0.5 = 1；
> - 树：1 × 4 × 0.5 = 2；
> - 该 land_region 总贡献 = 1 + 1 + 2 = 4（若全封闭 = 1 + 2 + 4 = 7，掉了 3 分）。

### 6.6 章节接口（[已确认]）

- 计分对象 = 收获状态 + 未闭合区域存活的植物 → 依赖 §5.1 / §5.3 / §5.6。
- 同级竞争修正 → 见 §6.3。
- 计分时段 = 游戏结束 → 依赖 §7.3 终局触发。
- 封闭判定 = `land_region` 的 land 边封闭状态 → 已在 §5.6.1 定义 `land_closed`，§6.5 复用；水网封闭状态不影响 §6.5 减半。
- 平局破平链 → 见 §6.4 第 4 步。

## 7. 回合流程

> 本章基于用户原话："游戏开始时，每名玩家从河流牌堆中抽取一张，合法放置在地图上，直到河流牌被抽完；接下来每名玩家需要在自己的回合做一下事情：1、从地形牌堆抽一张牌，合法放置在地图上；2、选择一项：扩张 / 种植 / 跳过；3、回合结束，进入下一个玩家的回合；直到所有地形块被抽完放置完，游戏结束，最后结算分数"。
>
> **r16 更新**：第 2 步改为"选择一项：**种植 / 跳过**"（§7.2.2）；原主动扩张取消，植物传播改由 §5.4.2 自动扩张承担。

### 7.1 初始化与开局长牌阶段（[已确认]）

#### 7.1.1 初始化（[已确认]）

1. **[已确认]** 棋盘以起始地块开局（具体规格见 §2.6 [TBD]，策划案起手式已实现 4-land 起始地块）。
2. **[已确认]** **发放种子**：每位玩家获得 3 种植物种子各 **2 枚**——草 / 花 / 树各 2，共 6 枚。这是用户原话"每名玩家开局时有 3 种种子个两个"的精确落地。
3. **[已确认]** **确定玩家回合顺序**：随机或商定，**当前默认按座位顺时针**（独玩 / 多人模式见 §9 #12）。

#### 7.1.2 长牌阶段（[已确认]）

**长牌阶段（River Setup Phase）**在初始化之后、主循环之前进行：

- **[已确认]** **按 §7.1.1 第 3 步确定的玩家顺序，依次**为每位玩家完成下列动作：
  1. 从**河流牌堆**抽取 1 张河流地块；
  2. **合法放置**该地块（拼接规则按 §3.2 全部约束，包括 BANK ↔ 水口的水渠改写）；
  3. 完成本次长牌动作，进入下一位玩家。
- **[已确认]** **长牌阶段终止条件**：当河流牌堆被抽完时，长牌阶段结束——按用户原话"直到河流牌被抽完"。
- **[待确认]** **河流牌堆容量与构成**：**一次性确定、由卡组配置决定**——卡组构成（含河流地块数量与牌面）将由设计者稍后提供（§9）。长牌阶段按序抽牌，抽完为止。
- **[已确认]** **长牌阶段不进行扩张 / 种植 / 跳过动作**——只放牌，不触发植物相关行为、不触发 §5.4 / §5.6 结算。

> 关键点：
>
> - 长牌阶段的目的是"建立初始河流骨架"——为后续玩家在地形扩张时提供 BANK 与潜在的水口。
> - 长牌阶段放置的合法地块**会**触发 §3.6 的 `BANK ↔ 水口 → 水渠` 永久改写——与主循环放牌共用同一拼接逻辑。

### 7.2 玩家回合（主循环）[已确认]

每位玩家在自己的回合中，**依次**执行下列三步：

#### 7.2.1 第一步：从地形牌堆抽 1 张牌（必做）[已确认]

- **[已确认]** 从**地形牌堆**抽取 1 张地形地块（不可跳过、不可重抽）。
- **[已确认]** **该地块至少有一种朝向可合法放置时，玩家必须放置**——按用户原话"合法放置在地图上"；不允许"能放但主动弃牌"。
- **[已确认]** **仅当抽到的地块在任何朝向、任何位置都无法合法放置时**（即任何朝向都不满足 §3.2 拼接约束），玩家才可**主动放弃**：该地块进入**弃牌堆**，本步结束，本玩家**不抽第二张**。
- **[已确认]** **合法性判定复用 §3.2 全套规则**——包括 BANK 改写、IR 跨界接口、中心地形约束（§2.4）。
- **[已确认]** **抽到的地块**经本次合法放置即落定。放置本身会立即触发 §3.6 的放置事件——其中包含 §5.4.2 的**自动扩张**与 §5.4.1 的**物种冲突驱逐**：刚放下的地块可能已紧邻某个已种植地块，其植物会自动扩张上来占据该格（不消耗任何人种子）。

> 关键点：
>
> - "不可重抽"与卡卡颂原版一致——遇到不能放的地块，自认倒霉。
> - 放下的地块**必然**触发 §3.6 的拼接事件伪代码（含水渠改写、IR 接口计算、V_L 重算的入口标记）。

#### 7.2.2 第二步：选择一项动作（必做）[已确认]

从下列两项中**任选一项**执行——不能多选、不强制。（r16 变更：原"扩张 / 种植 / 跳过"三选一改为"种植 / 跳过"二选一；主动扩张动作取消，由 §5.4.2 自动扩张取代。）

#### A. 种植（Plant）[已确认]

- **[已确认]** 玩家**可以**在本回合放置完地块后放置一株植物：
  1. **点击目标格**：仅可点击**当前玩家本回合刚放置**且满足 §5.8 前置检查的地形块——①包含可种植土地；②当前**没有被任何植物占据**（不论是自己的还是别人的）；③所属每个 `land_region` 均未锁定（§5.6.1，含收获植物的区域不可再种）。其它棋盘地块悬停或点击均不产生种植反馈；
  2. **选择物种**：任选一种（草 / 花 / 树），从自己的种子集合扣除 1 枚对应种类种子；
  3. 在目标格种下一株该物种植物（进入**存活**状态，§5.3）。
- **[已确认 · r16.2]** 目标格**只能是本回合新放置的地块**；即使历史地块空置、可种植，也不可被主动种植。
- **[已确认]** **允许种进已有植物的土地块**：只要目标格本身无植物即可；若目标格所在 `land_region` 已有**其他物种**的植物，按 §5.4.1 立即触发驱逐结算（新种的低优先级植物会被立即移除并退种——种植前请三思）；若是**同物种**则与既有植物同级共存（计分见 §6.3）。
- **[已确认]** 每回合**最多**执行 1 次种植动作。
- **[提案 · r16.1 收窄]** 已闭合区域的种植：仅当目标格所在区域**未锁定**（区域内无收获植物，§5.6.1）时合法——即只能种进"全死亡"或无植物的闭合区域；新植物在下一结算窗口（§7.2.3）立即按 §5.6.2 单独结算，水量按结算时点 V_L 现值。含收获植物的区域**整体禁种**（含原主）。

> 关键点：
>
> - 种植的收获 / 死亡**不在种植时判定**——统一延迟到所在土地块全封闭结算（§5.6）。
> - 种植**不再要求区域无主**（r15 的 §7.2.2.B 第 2 条"land_region 内没有别人的植物"已不适用）；但主动种植仍必须落在当前玩家本回合新放置的地块，区域归属由物种优先级与同级竞争机制动态裁决。

#### B. 跳过（Pass）[已确认]

- **[已确认]** 玩家**跳过本步骤的全部动作**——不种植，直接进入 §7.2.3。
- **[已确认]** 跳过的回合**不影响**植物的结算——§5.4 / §5.6 各自的结算时点照常工作。

#### 7.2.3 第三步：回合结算窗口与顺序轮转（r16 更新）

玩家执行完 §7.2.2 选定动作（或跳过）后，进入**结算窗口（Settlement Window）**：

1. **[已确认]** **解决物种冲突**：本回合种植 / 自动扩张引入的不同物种共存 → 按 §5.4.1 立即驱逐（移除 + 退还种子）。放置阶段的冲突已在 §3.6 事件内处理，这里兜底处理种植动作引入的冲突；
2. **[已确认]** **检查所有 `land_region` 的全封闭状态**（按 §5.6.1），对**本次新闭合**的土地块执行 §5.6.2 的两阶段结算（阶段 A 死亡/收获判定；阶段 B 统一退还种子——死亡移除、收获保留）；
3. **[提案]** **已闭合区域内新种植物**的立即结算：本回合种进未锁定闭合区域的植物，按 §5.6.2 单独结算一次（水量判定 + 区域退种；若产生收获则区域随即锁定，§5.6.1）；
4. **[已确认]** **记录本回合种植 / 自动扩张顺序**（§5.8"种植顺序字段"在结算窗口末尾写入）。

> r16 变更：r15 的"重算 V_L / 重分配水源 / 判定形态"三个全局步骤取消——水量只在闭合结算时使用（§5.5 / §5.6），存活 / 收获 / 死亡之外没有中间形态。

随后：

- **[已确认]** 结算完成后进入下一位玩家（按 §7.1.1 第 3 步确定的玩家顺序）。
- **[已确认]** **结算** = 玩家动作**之后立即触发**，下一位玩家行动**之前**完成；这样每位玩家行动前的棋盘状态是稳定的。

> 关键点：
>
> - 结算窗口是 §5 全部驱逐、闭合与退还规则的触发器——每次回合切换都重新走一遍；
> - 结算后的玩家回合状态必须是**稳定**的——下一位玩家看到的棋盘 = 该回合结算后的棋盘；
> - 一位玩家的动作若触发了 §5.6 全封闭结算（死亡清格 / 收获退种）或 §5.4.1 驱逐（立即退种），都在结算窗口内执行完毕——下一位玩家看到的是已稳定的状态。

### 7.3 终局触发与最终结算（[已确认]）

#### 7.3.1 终局触发条件（[已确认]）

- **[已确认]** **当且仅当**地形牌堆被抽完且**所有抽出的合法地形地块已被放置**时，游戏结束——按用户原话"直到所有地形块被抽完放置完，游戏结束"。
- **[已确认]** **触发位置**：当前回合（§7.2.3）结算窗口**结束后**——本回合**不进入下一位玩家**，直接走 §7.3.2 终局流程。
- **[已确认]** **§7.2.1 抽到的地块若最终被弃置**（无法合法放置），它**不计入**"已放置"集合——游戏继续；只有当抽到的合法地块全部被放置、且牌堆为空时，游戏才结束。

> 关键点：
>
> - "抽完且放置完"是**复合终止条件**——既要求牌堆空，又要求所有合法抽取的地块都已被处理（放置或弃置不影响终止）。
> - 现行玩家的最后回合仍然完整执行 §7.2.1 / §7.2.2 / §7.2.3——直到 §7.2.3 结算窗口结束才检查终局条件。

#### 7.3.2 终局结算流程（r16 更新）

1. **[已确认]** **确认结算完整性**（§5.7）：已闭合土地块已在持续结算中处理完毕（收获保留占格 / 死亡移除）；已闭合区域内仍在存活状态的植物补跑一次 §5.6.2；未闭合土地块保持存活状态——r16 **没有**终局形态升级步骤；
2. **[已确认]** **§6 计分**：按 §6.1 / §6.2 计算每位玩家得分（含 §6.3 同级竞争、§6.5 封闭修正）；
3. **[已确认]** **宣布胜负**（§6.4）：比较得分，最高分者胜出。

#### 7.3.3 终局后的退还 / 清场（r16 更新）

- **[已确认]** **终局不退还未闭合区域的种子**——种子退还的唯一触发器是全封闭结算（§5.6），其路径已在主循环的 §7.2.3 结算窗口里持续处理；终局不再额外退还。
- **[已确认]** 收获植物保留至终局计分完成后，游戏即结束；死亡与被驱逐的植物已在棋盘上移除，无需处理。
- **[已确认]** 已闭合区域内死亡空出的格在终局**不可再种植**（终局后没有新的种植窗口）。

### 7.4 边界与关键点（[已确认]）

- **[已确认]** **种子用完即停**：当玩家某物种的种子为 0 时，该物种的种植动作不可发起——玩家可以种植其他物种，或选择跳过。**自动扩张不消耗种子**，因此不受种子余量限制（§5.4.2 [提案]）。
- **[已确认]** **动作选择与回合顺序解耦**：玩家本回合种植消耗的种子不会影响其他玩家的动作——驱逐与闭合结算集中在 §7.2.3 结算窗口同步生效。
- **[已确认]** **自动扩张的战略含义**：放置地块本身就是一种间接的领土行为——在对手已种植地块旁放牌，等于把新格让给对手的植物自动占据；在自己的植物旁放牌，则免费扩张自己的版图。
- **[已确认]** **持续结算的设计含义**：每位玩家每次行动后都会触发一次结算窗口；这与"只在游戏结束结算一次"的传统桌游不同——本规则书把 §5.6 全封闭结算从"终局一次性"搬到"每回合持续性"——保证玩家能在每一步看到"死亡清格 / 收获退种"的反馈。
- **[已确认]** **玩家顺序与游戏结束**：最后一位玩家执行完自己回合后，若牌堆已空，则不再轮转，直接进入 §7.3 终局流程；具体哪个玩家的最后回合触发了终止，由游戏运行时的牌堆剩余数决定（不再引入"最后 N 圈"之类限制）。
- **[已确认]** **独玩模式（待确认** — §9 #12）：若仅 1 位玩家，跳过玩家顺序轮转，玩家始终同一回合；其它规则（开局、单步流程、终局）保持不变。
